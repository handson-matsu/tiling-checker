# タイリング確認アプリ

正方形の紙を三角形ピースに分割し、左右に分けたマークを組み合わせる日本語教材です。正方形の外形は保ち、マークは紙の内側に置きます。

## 起動・公開

```sh
python3 -m http.server 8000
```

http://localhost:8000 を開きます。ES ModulesのためHTTPサーバーを使ってください。描画・操作には外部ライブラリ・ビルドは不要です。ページ読み込み時のアクセス記録だけGASに送信し、通信失敗でも操作できます。GitHub Pagesでブランチのルートフォルダーを公開できます。コミット・プッシュ・公開設定は実施していません。

## ピースとペアの新しい定義

最初に4・6・8ピースを選び、その後に配置と各ペアのマーク・色、各ピースの表裏を設定します。元の2ペアを分割モードに引き継ぐ方式は廃止しました。

| モード | ペア数 | 構成 |
|---|---|---|
| 4ピース | 2 | 通常の三角形2枚で1ペア |
| 6ピース | 3 | 分割した2辺がそれぞれ独立したペア、残りの通常2辺がもう1ペア |
| 8ピース | 4 | 各辺の半分2ピースがそれぞれ1ペア |

各ペアは常に異なる2ピースを所有します。半分ピースは同じ辺の2区間で、相補的な右半分・左半分のペアになります。たとえば上下を分割した6ピースでは、上辺左＋右がA、下辺右＋左がB、残りの左右がCです。AとBには別々のマークと色を指定できます。新規ペアには可能な限り異なる初期マーク・色を割り当てます。

### 配置と図上の選択

- 4ピース：「対／隣」と「基準の辺」で配置を選べます。完成タイル上の2ピースを順に選ぶと、その2枚をペアにし、残りの2枚でもう1ペアを作ります。キーボードのEnter・Spaceでも選べます。
- 6ピース：「対／隣」と「基準の辺」で分割する2辺を選びます。対2通り・隣4通り、計6種類の実現可能な構成を扱います。各分割辺の2枚は同じ辺のペアに固定し、残りの通常2枚も1ペアです。
- 8ピース：各辺の2枚がA〜Dです。全辺分割のため対／隣・基準辺は無効になります。
- 図で選んだピースとそのペア相手は緑の点線で強調します。別の辺の半分ピース同士、半分と通常のピースの組合せは許可しません。
- 図でのペア変更は表裏を変更しません。各ピースの表裏は左のチェックで独立して指定します。

同じ辺の2区間の切断軸は、それぞれ外周の辺に一致させます。このため同じ辺の左右半分はタイル内では離れて表示されます。相補的なペアとして管理し、完全な形は隣接タイルとの境界で確認する方式です（ユーザー確認済み）。

## マーク・描画・表裏

ハート、スペード、クローバー、ダイヤ、星（五芒星）、丸（円）の6種類と8色に対応します。星と円も縦の対称軸で二分します。円は完成時に縦横同寸になるスケールです。マークは各辺区間の長さに比例して縮小し、実際のピース内に収めます。

通常の対角線は全モードで残り、分割辺の中点と中心へ点線を追加します。外枠とマーク輪郭は濃い実線です。表面は白、裏面は #DCE2E6。裏面マークは淡色になります。「裏面の色を淡くする」がOFFの場合は背景を白、マークを通常色にします。

有効な表裏状態は4・6・8個です。分割時は親の表裏を両方へ継承し、分割を戻すと辺に沿った先の区間を採用します（上は左、右は上、下は右、左は下）。同じピースIDや同じペア構成を保つ設定変更では状態を引き継ぎます。

## タイリング・判定・PNG

4×4の16枚を配置します。初回クリックで選択、選択中の再クリックで90度回転、ボタンで反転。外側クリックで選択解除します。反転で全ピースの表裏・背景・マーク色・左右の向きが反転し、2回反転で戻ります。回転で表裏は変わりません。設定変更後もタイリングの回転・反転を保ちます。

隣接24辺で、区間の両端点、マークの種類、相補的な左右、マークの頭から底への方向、境界で鏡映した実際の輪郭座標を比較します（許容距離0.001、辺長200）。色とペア名そのものは判定しません。同じ種類の幾何学的に対応する半分なら、別ペアでも一致します。通常辺と半分辺は現在のマークライブラリでは位置・寸法が異なるため不一致です。不一致の辺を太い赤い実線と白丸の×で表示し、外周は判定しません。

分割した各辺が独立した別マークになるため、6・8ピースの初期状態では全24辺の一致とは限りません。設定やタイルの向きを変えて調べてください。

PNGは単体1800×1800／全体3200×3200。分割線・表裏の背景・マークと全体画像の不一致強調を含みます。設定UI、タイリング選択枠、図上ペア選択の強調枠は除外します。ファイル名にピース数を含みます。

## 実装

- `src/pairing.js`：2つのピースIDを所有するペアの生成、マーク・色の初期設定。2組に固定せず、将来の6組も扱える汎用データ構造です。
- `src/segments.js`：図形に依存しない0〜1の辺区間と補間。
- `src/square.js`：正方形の分割、4／6／8ピースとペア構成、図上組替え、ピースの座標。
- `src/marks.js`：半分マークのベジェ／折れ線定義。円は3次ベジェ近似、星は正五芒星の輪郭です。
- `src/appearance.js`：元ピースの裏面指定 XOR タイルの反転で表裏と色を共通判定。
- `src/geometry.js`：座標変換と区間・輪郭の一致判定。
- `src/app.js`：設定UI、図上ピース選択、SVG、タイリング操作、PNG保存。

ペアは `members: [pieceId, pieceId] / mark / color`、ピースは `id / edge / start / end / index / pair / half` を持ちます。ペア数に上限2の仮定はありません。実際の正六角形の分割・配置はまだ実装していません。

## 今回の確認結果

自動テスト40件すべて成功。ブラウザで4・6・8ピースの操作、図上のペア組替えと無効組合せの拒否、6ピースの独立した星／円・色設定、隣と基準辺による分割変更、個別表裏と全体反転、2回反転での復元を確認しました。全ペアを円にした8ピースで24辺すべての一致、異なる種類では不一致となることも確認しました。画面幅390pxで横はみ出しがなく、4ペア・8ピースの設定が使えます。

星・円を含む6ピースの単体PNG（1800×1800）と4ペアの8ピースのタイリングPNG（3200×3200）を実際に保存し、表示を確認しました。ブラウザの実行時エラーはありませんでした。


## 中央の手

「中央の手を表示する」は初期ONです。人差し指を上に立て、親指を左へ出した手のひらをSVGで描きます。高さ58（タイル辺長200の約29%）で、以前の魚より大きくしました。ピース名・表裏の文字は図上では常に表示しません。手をOFFにすると中央の目印は空になります。ピース名と表裏は左の設定で確認・変更できます。

手はタイル全体に後から描いた補助マークです。各ピースの表裏や淡色設定では変わりません。通常は #F5C49B と濃い茶色の輪郭、タイル全体の反転時は #B7D9E8 と濃い青の輪郭です。指の方向で回転、親指の位置で鏡映を判別できます。タイルと同じグループで回転・反転し、4回転／2回反転で形と色が戻ります。表示ON/OFFと反転色は完成タイル・16枚・PNGへ共通で反映します。

`src/hand.js` にSVG図形、タイル反転だけで決まる色、向きのテスト用ランドマークを定義しています。

## アクセス記録（GAS）

`src/access-counter.js` の `ACCESS_CONFIG` にURLと `app: 'tiling-checker'` を設定しています。URLとGETオプションは、同じGitHubフォルダーの `hit-and-blow/access-counter.js` と `coin-shooting/access-counter.js` の実装を確認して合わせました。アプリ名だけをクエリで送ります。

- ページの初期化後に1回だけGET送信します。`mode: no-cors / cache: no-store / credentials: omit / keepalive: true`。
- 操作・設定変更・リセット・PNG保存では送信しません。再読み込みは新しいdocumentなので新たに1回送信します。
- 同期例外と非同期の通信失敗を吸収し、再試行しません。
- 既存方式は応答を読み取れないため、アクセス数を画面表示しません。送信成功やGAS内の実記録件数もアプリ側では断定しません。

## 裏面色の初期設定と不一致表示

「裏面の色を淡くする」は初期ONです。表面は #FFFFFF、裏面は #DCE2E6。OFFにすると両面とも白です。ピース個別の表裏とタイル全体の反転で同じ処理を使い、PNGにも反映します。

「不一致箇所を表示する」も初期ONです。OFFで警告線と×だけを非表示にし、判定・一致数／不一致数の集計は続けます。この表示設定は回転・反転・個別／全体リセット・設定初期化でも保持します。ページの再読み込み時はONに戻ります。PNGは現在の表示設定を反映します。

`src/mismatch.js` の最前面レイヤーで、共通する境界につき1本の鮮やかな赤い実線を描きます。線幅は辺長の3%、中央白丸の半径は辺長の4.5%で、両端にも小さな丸を付けます。中央は白丸に赤い×です。半分モードでも辺全体の判定につき1個だけ描画し、全レイヤーを pointer-events:none にしてクリック操作を透過します。選択枠は従来の濃い破線のままです。

追加5件を含む自動テスト55件が成功し、ブラウザ統合テスト15件も成功しました。初期ON、ピース／タイル全体の反転と背景、ON/OFFと集計の独立、操作・リセット後の設定維持、警告の最前面表示・重複防止・クリック透過、4／6／8ピース、PNG用SVGへの背景と警告設定の反映を確認しました。アクセス記録はテスト内でモック化しています。


## ピース情報の文字表示

完成タイルとタイリングのピース名・表裏ラベルは常に描画しません。手の表示設定とは独立しており、両PNGにも含めません。不一致表示の白丸の×は従来どおりです。4・6・8ピースの表裏は設定パネルの名前付きチェックで確認・変更できます。ブラウザテストで各モードの手ON/OFF、文字なし、PNG用SVGにピース文字がないことを確認します。


## 選択タイルの近くの反転ボタン

選択すると近くに「↔ 裏返す」を表示します。原則右側、右端では左側、収まらない場合は下・上・画面内の位置へ調整します。近隣のタイルの中央を避けやすいよう、辺の上端付近に寄せています。スクロール、画面サイズ・向きの変更、図のサイズ変更でも追従し、選択解除／選択タイルが画面外の場合は非表示です。

HTMLのボタンをSVGの外に重ね、高さ44px以上・幅104px以上のタッチ領域を確保します。従来の反転ボタンと同じ処理で、反転後も選択を保ち、クリックの伝播でタイルが回転したり選択解除されたりしないようにしています。SVG外の操作UIなのでPNGには含みません。アクセス記録も追加送信しません。

`src/floating-flip.js` の配置テスト5件を含む自動テスト60件とブラウザ統合テスト16件が成功しました。Node/npmがPATHにないため、自動テストは付属JavaScript環境で同じテスト関数とNodeのassertを実行しています。実ブラウザで幅1440px／820px／390px、右端・下端の配置と反転、隣のタイルの選択と再クリック回転を確認しました。タッチのイベント列も統合テストで確認しました。実機iPadでの検証は未実施です。
